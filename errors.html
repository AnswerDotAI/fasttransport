Purpose And Design

Every client built on these transports fails in the same three ways: an HTTP error status, a transport-level failure such as a timeout, or an error event arriving mid-stream. APIError is the single type all three become, so a caller writes one except regardless of which provider answered or which client library made the call.

_to_text

Best-effort stringify helper.

_retryable

Classify transient/retryable API failures.

_req_id

Extract provider request id header when available.

All three major providers (OpenAI, Anthropic, Gemini) consistently return {"error": <dict>} with a message field inside, so the primary isinstance(err, dict) branch handles them all. The remaining branches are defensive fallbacks for edge cases:

  • elif err is not None — error is a string (e.g. proxy/gateway errors)
  • else — no error key at all (e.g. OAuth error_description, or detail-only responses)
  • except Exception: raw = self.text — non-JSON responses from CDNs/gateways

Key per-provider differences in the dict branch: - OpenAI: error.{message, type, code, param}, top-level status (int) - Anthropic: error.{type, message} only — no code or status - Gemini: error.{code (int), message, status (string), details} — status carries the semantic gRPC code (e.g. INVALID_ARGUMENT)

The status→code promotion at the end ensures semantic codes like Gemini’s "INVALID_ARGUMENT" are preferred over numeric HTTP codes.

All three providers use different SSE error event shapes:

  • OpenAI (docs): flat {code, message} — no nested error key, code is a string enum (e.g. "rate_limit_exceeded")
  • Anthropic (docs): {type: "error", error: {type, message}} — no code or status
  • Gemini (docs): {error: {code, message, status, details}} — code is numeric, status is the semantic gRPC code

The extraction logic: 1. isinstance(event["error"], dict) → use nested dict (Anthropic, Gemini) 2. isinstance(event, dict) but no nested error → use whole dict (OpenAI flat shape) 3. Not a dict at all → wrap as {"message": stringified} (defensive fallback)

NB: Unlike error(), this function does not promote Gemini’s semantic status over numeric code — so Gemini returns code=500 rather than code="INTERNAL". This may be worth aligning.

RequestError.api_error

def api_error(
    *, provider:str='', model:str='', endpoint:str=''
):

Build APIError from httpx2 RequestError (transport-level failure).

req = httpx2.Request("POST", "https://api.openai.com/v1/chat/completions")

err = httpx2.ConnectError("connection refused", request=req)
ae = err.api_error(provider="openai", model="gpt-4o")
test_eq(ae.retryable, True)
test_eq(ae.error_type, "ConnectError")
test_eq(ae.endpoint, "POST /v1/chat/completions")
test_eq(ae.provider, "openai")
test_eq(ae.model, "gpt-4o")
test_is(ae.raw, err)

err = httpx2.ReadTimeout("read timed out", request=req)
test_eq(err.api_error().retryable, True)
test_eq(err.api_error().error_type, "ReadTimeout")

err = httpx2.RemoteProtocolError("server disconnected", request=req)
test_eq(err.api_error().retryable, True)

err = httpx2.UnsupportedProtocol("bad scheme", request=req)
test_eq(err.api_error(provider="anthropic").retryable, False)
test_eq(err.api_error().error_type, "UnsupportedProtocol")

err = httpx2.DecodingError("bad gzip", request=req)
test_eq(err.api_error().retryable, False)
try: httpx2.get("http://127.0.0.1:1/nope", timeout=1)
except httpx2.RequestError as exc: ae = exc.api_error(provider="local")
test_eq(ae.retryable, True)
test_eq(ae.provider, "local")
test_eq(ae.endpoint, "GET /nope")
assert isinstance(ae.raw, httpx2.RequestError)

Works with any API — the provider and model fields are optional context that higher-level libraries can populate:

# Generic API error — no provider/model needed
gh_evt = {"error": {"message": "API rate limit exceeded", "documentation_url": "https://docs.github.com/rest"}}
print(api_error_from_event(gh_evt, endpoint="GET /repos/{owner}/{repo}"))
